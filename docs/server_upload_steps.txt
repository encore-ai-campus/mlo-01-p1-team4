EC2 서버 연결 및 파이프라인 실행 순서

기준 정보
- 서버 IP: 52.78.120.68
- SSH 계정: ec2-user
- 키 파일: C:\Users\Playdata\Downloads\encore_new_key.pem
- 서버 프로젝트 폴더: /home/ec2-user/first-pj-web
- 로컬 업로드 폴더: C:\Users\Playdata\Desktop\올릴파일\first-pj-web

1. 키 파일 위치 확인

Windows PowerShell에서 실행한다.

Test-Path "C:\Users\Playdata\Downloads\encore_new_key.pem"

True가 나오면 키 파일 위치가 맞다.

2. 서버에 접속

Windows PowerShell에서 실행한다.

ssh -i "C:\Users\Playdata\Downloads\encore_new_key.pem" ec2-user@52.78.120.68

3. 서버의 기존 프로젝트 폴더 확인

서버에 접속한 뒤 실행한다.

cd /home/ec2-user/first-pj-web
pwd
ls -la

.env가 이미 있으면 그 파일을 계속 사용한다.

4. 프로젝트 파일 업로드

서버에서 빠져나온 뒤 Windows PowerShell에서 실행한다.

exit

scp -i "C:\Users\Playdata\Downloads\encore_new_key.pem" -r `
"C:\Users\Playdata\Desktop\올릴파일\first-pj-web\src" `
"C:\Users\Playdata\Desktop\올릴파일\first-pj-web\sh" `
"C:\Users\Playdata\Desktop\올릴파일\first-pj-web\sql" `
ec2-user@52.78.120.68:/home/ec2-user/first-pj-web/

업로드 대상은 src, sh, sql이다.
.env, .pem, 로그 파일은 업로드하지 않는다.

5. 업로드 결과 확인

다시 서버에 접속한다.

ssh -i "C:\Users\Playdata\Downloads\encore_new_key.pem" ec2-user@52.78.120.68
cd /home/ec2-user/first-pj-web
find src sh sql -maxdepth 1 -type f

6. 환경변수 설정 확인

nano .env

.env에는 다음 값이 있어야 한다.

MYSQL_HOST=팀에서 정한 MySQL 서버 주소
MYSQL_PORT=3306
MYSQL_DATABASE=project1
MYSQL_USER=팀에서 정한 MySQL 계정
MYSQL_PASSWORD=팀에서 정한 MySQL 비밀번호

비밀번호는 이 문서나 Git에 기록하지 않는다.

7. API 연결 확인

curl -sS --max-time 10 http://192.168.0.51:4000/api/v1/public-key

JSON 응답이 나오면 API 연결이 된 것이다.
응답이 없으면 크론탭보다 먼저 API 서버 접근 문제를 확인한다.

8. Python 가상환경과 패키지 설치

python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r src/requirements.txt
deactivate

run_car_pipeline.sh는 .venv 안의 Python을 사용한다.

9. MySQL과 테이블 확인

아래 명령으로 .env를 현재 셸에 적용한다.

set -a
source .env
set +a

mysql -h "$MYSQL_HOST" -P "$MYSQL_PORT" \
-u "$MYSQL_USER" -p "$MYSQL_DATABASE" \
-e "SHOW TABLES LIKE 'car_listing';"

car_listing이 나오면 테이블이 이미 있는 것이다.
없는 경우에만 아래 명령을 실행한다.

mysql -h "$MYSQL_HOST" -P "$MYSQL_PORT" \
-u "$MYSQL_USER" -p < sql/project1_schema.sql

10. 테스트 범위 설정

nano src/car_api_crawler.py

처음 테스트할 때는 MAX_PAGES = 1로 설정한다.
한 페이지를 수집한 뒤 전체 흐름을 확인하기 위한 설정이다.

11. 파이프라인 수동 실행

chmod +x sh/run_car_pipeline.sh
./sh/run_car_pipeline.sh

이 명령은 다음 순서로 실행한다.

1) car_api_crawler.py가 API에서 차량을 가져온다.
2) 가져온 차량을 MySQL car_listing에 저장한다.
3) vehicle_quality.py가 적재된 차량을 검사한다.
4) 품질 결과가 PASS인지 확인한다.
5) 전체 실행 결과를 로그에 남긴다.

12. 실행 결과 확인

tail -n 30 logs/car_pipeline.log
tail -n 30 src/car_api_crawler.log
cat quality_check_output/quality-report.json

quality_status가 PASS인지 확인한다.

MySQL 적재도 확인한다.

mysql -h "$MYSQL_HOST" -P "$MYSQL_PORT" \
-u "$MYSQL_USER" -p "$MYSQL_DATABASE" \
-e "SELECT COUNT(*) AS car_count FROM car_listing;"

13. 전체 수집 설정

테스트가 성공하면 다시 파일을 연다.

nano src/car_api_crawler.py

MAX_PAGES = 0

MAX_PAGES가 0이면 API의 next_url이 없어질 때까지 전체 페이지를 수집한다.

14. 크론탭 등록

서버에서 실행한다.

crontab -e

아래 한 줄을 추가한다.

0 * * * * /usr/bin/bash /home/ec2-user/first-pj-web/sh/run_car_pipeline.sh

저장한 뒤 등록 결과를 확인한다.

crontab -l

위 설정은 매시 정각에 파이프라인을 실행한다.

15. 로그 순환 설정

서버에서 실행한다.

sudo cp sh/car_pipeline.logrotate /etc/logrotate.d/first-pj-web
sudo chmod 644 /etc/logrotate.d/first-pj-web
sudo logrotate -d /etc/logrotate.d/first-pj-web

-d는 실제 로그 삭제 없이 설정만 확인하는 옵션이다.

최종 확인 순서

1) API 응답 확인
2) .env 확인
3) Python 패키지 설치
4) car_listing 테이블 확인
5) 한 페이지 수동 실행
6) 로그와 품질 결과 확인
7) MAX_PAGES를 0으로 변경
8) 크론탭 등록
9) crontab -l로 등록 확인

주의

- .pem 파일은 서버나 Git에 올리지 않는다.
- .env와 MySQL 비밀번호는 Git에 올리지 않는다.
- 처음부터 전체 수집하지 말고 한 페이지 테스트 후 전체 수집한다.
- cron은 .env를 자동으로 읽지 않으므로 run_car_pipeline.sh가 .env를 읽도록 한다.
